# rules-zed — контекст проекта

Документационный проект: единый источник истины для переноса настроек
Zed AI-агента на чистую машину. «Сборка» — это сам файл `rules-Zed.md`
(канон), который целевой агент читает и распаковывает.

## Состав
- `rules-Zed.md` — канон: §1 глобальный `AGENTS.md` (7 секций), §2 skill
  `git-workflow`, §3 провайдер (рекомендация + ссылка на `zed-free-llm`),
  §4 нюансы Zed, §5 skill `project-doctor`, §6 чек-лист настройки
- `README.md` — обёртка: состав, «как использовать», проектные правила,
  конфиденциальность
- `AGENTS.md` — этот файл (контекст проекта; глобальные правила не дублирует)
- `LICENSE`, `.gitignore` — MIT; игноры

## Инвариант: канон ↔ установленные файлы
Установленные глобальные файлы зеркалят канон:
- §1 → `%APPDATA%\zed\AGENTS.md`
- §2 → `~/.agents/skills/git-workflow/SKILL.md`
- §5 → `~/.agents/skills/project-doctor/SKILL.md`
При правке канона — синхронизировать установленные файлы (и наоборот),
затем проверить (diff, число секций). Дивергенция канона и установленных
файлов — главный известный дефект этого проекта.

## Смежные репозитории
- Подробная настройка LLM в Zed — `zed-free-llm`
  (https://github.com/IgerOK/zed-free-llm, локальный клон `D:\zed_prj\API-LLM`).
  Здесь — только рекомендация Agnes / `agnes-3.0-flash` + ссылка; дублировать
  детали настройки запрещено.
- Глобальное хранилище этого проекта — https://github.com/IgerOK/rules-zed.
  Локальный `.git` удалён (проект завершён); актуализация содержимого —
  ручным переносом файлов через браузер (Add file → Upload files).

## Нет сборки/тестов
Документационный проект: проверка = чтение канона, сверка числа секций (§6).
Команд сборки и тестов нет.

## Подводные камни Windows (специфичные для этого воркфлоу)
- `nul` — зарезервированное имя: лишний файл в корне удалять из `cmd`:
  `del \\?\D:\zed_prj\rules-zed\nul` (cmdlet `Remove-Item` не справляется,
  но .NET `[System.IO.File]::Delete("\\?\...")` с префиксом `\\?\` работает).
- В `.gitignore` `#` — только в начале строки: инлайн-комментарий ломает
  паттерн (проверять `git check-ignore`).
- Терминал Zed — POSIX-шелл (Git Bash): искажает Windows-пути — для таких
  операций явно вызывать `cmd` или `powershell`.

## Конвенции правки
- Точечные диффы, не перезаписывать файлы целиком.
- При изменении структуры `rules-Zed.md` держать согласованными: нумерацию
  §1–§6, перекрёстные ссылки на секции, чек-лист §6 (число секций),
  README («Состав», «Проектные правила»).
- Секреты в файлы не записывать — только плейсхолдеры.
- Внешний fence §2 канона — 4 бэктика (внутри вложенный блок ```` ```gitignore ````);
  при правке §2 не снижать до 3 — иначе блок разрушится.
