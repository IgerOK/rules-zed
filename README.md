# Settings Zed

Проект конфигурации AI-агента Zed IDE. Единый источник истины для
переноса настроек на чистую машину: глобальные правила, skill, настройка
провайдера/модели и иллюстрация.

## Состав

| Файл | Назначение |
|---|---|
| [`rules-Zed.md`](rules-Zed.md) | Объединённая конфигурация Zed-агента: §1 глобальный `AGENTS.md`, §2 skill `git-workflow`, §3 провайдер и модель (рекомендуется Agnes, допустим любой LLM-агрегатор), §4 нюансы (skills, обновления Zed, проектный `AGENTS.md`), §5 чек-лист проверки |
| [`agnes1high.png`](agnes1high.png) | Скриншот настройки провайдера в Zed (Settings → Models → API Providers): OpenAI-совместимый эндпоинт Agnes, модель с reasoning effort **High** (ключ маскирован, хранится в системном keychain, не в `settings.json`) |
| [`.gitignore`](.gitignore) | Игнорируемые файлы для публикации в Git (ОС-хлам, служебные каталоги Zed, временные файлы) |
| [`LICENSE`](LICENSE) | Лицензия проекта — MIT (английский оригинал + неофициальный перевод на русский) |

## Как использовать (новая машина)

1. Установить Zed: https://zed.dev/?ref=taaft (Windows — инсталлятор
   `Zed-x.x.x-windows-installer.exe` или портативный `.zip`; macOS — `.dmg`;
   Linux — `tar.xz`). Обновление — ставить **поверх** (не удалять `AppData\Roaming\Zed`
   и `AppData\Local\Zed` — там настройки, глобальный `AGENTS.md`, история чатов).
   Текущая версия: `Ctrl+Shift+P` → `Zed: About`.
2. Установить Git (если отсутствует): https://git-scm.com (Windows — инсталлятор;
   Linux — системный пакетный менеджер `apt`/`dnf`/`pacman`; macOS — `brew install git`).
3. Скопировать `rules-Zed.md` на машину и выполнить его инструкции §1–§5
   (вручную или передать их агенту Zed целиком).
4. Настроить провайдера — это ручной шаг в Settings → Models (§3 документа);
   API-ключ вставляется только туда и не попадает в файлы.
5. Открыть **новый** агент-чат: список skills и правил фиксируется при создании
   треда и в уже открытых диалогах не обновляется (перезапуск Zed не помогает —
   старые чаты восстанавливаются со «замороженным» снимком).

## Проектные правила

Глобальный `AGENTS.md` покрывает общие правила. Для нового проекта с
проекто-специфичным (команды сборки/запуска, стек, конвенции, запретные зоны)
целесообразно добавить в его корень файл `AGENTS.md` **с дополнительным**
описанием — записывать туда только отличие от глобального, без дублирования,
и поддерживать в актуальности.

## Конфиденциальность

Файлы проекта не содержат секретов: API-ключи и токенные значения передаются
только через настройки Zed (system keychain), а в документах стоят плейсхолдеры
(`<USER>`, `User Name`, `email@example.com`, «ваш ключ LLM»).
