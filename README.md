# Settings Zed

Проект конфигурации AI-агента Zed IDE. Единый источник истины для
переноса настроек на чистую машину: глобальные правила (`AGENTS.md`,
7 секций), skills `git-workflow` и `project-doctor`, настройка
провайдера/модели.

## Состав

| Файл | Назначение |
|---|---|
| [`rules-Zed.md`](rules-Zed.md) | Единый источник истины: §1 — глобальный `AGENTS.md` (7 секций), §2 — skill `git-workflow`, §3 — провайдер и модель (рекомендация Agnes / `agnes-3.0-flash`; подробная настройка LLM — https://github.com/IgerOK/zed-free-llm), §4 — нюансы Zed (skills, обновления, проектный `AGENTS.md`), §5 — skill `project-doctor`, §6 — чек-лист настройки |
| [`AGENTS.md`](AGENTS.md) | Контекст проекта: инвариант «канон ↔ установленные файлы», смежные репозитории, подводные камни Windows, конвенции правки (глобальные правила не дублируются) |
| [`.gitignore`](.gitignore) | Игнорируемые файлы для публикации в Git (ОС-хлам, служебные каталоги Zed, временные файлы) |
| [`LICENSE`](LICENSE) | Лицензия проекта — MIT (английский оригинал + неофициальный перевод на русский) |

## Что реализуют правила (в порядке выполнения)

Перечень — в порядке, как агент выполняет инструкции канона `rules-Zed.md` (см. шаг 3 «Как использовать»); нумерация внутри пунктов — своя, в скобках — раздел канона:

1. **(§1) — глобальный `AGENTS.md`** — файл из 7 секций (Коммуникация, Git, Python, Project Bootstrapping, README, Оболочка Windows, Лимиты и экономия токенов). Создаётся в OS-зависимом пути: Windows — `%APPDATA%\zed\AGENTS.md`, Linux — `~/.config/zed/AGENTS.md`, macOS — `~/Library/Application Support/zed/AGENTS.md`.
2. **(§2) — skill `git-workflow`** — файл `~/.agents/skills/git-workflow/SKILL.md`: проверка и настройка Git (установка при отсутствии, `init`, `.gitignore`, настройки пользователя, статус), коммит после изменения; remote и пуш — только по отдельной просьбе.
3. **(§5) — skill `project-doctor`** — файл `~/.agents/skills/project-doctor/SKILL.md`: диагностика среды при открытии проекта (манифесты, зависимости, переменные окружения, линтеры).
4. **(§3) — LLM-провайдер/модель** — в настройках Zed (файлов не создаёт): рекомендация Agnes / `agnes-3.0-flash`, подробная инструкция — репозиторий `zed-free-llm`; API-ключ только в настройках Zed.
5. **(§6) — проверка** — чек-лист агента: файлы на месте, провайдер настроен, оба skill доступны в новом агент-чате.

Раздел (§4) файлов не создаёт — это нюансы Zed (где живут skills, правило «нового чата», обновление Zed, проектный `AGENTS.md`).

## Зачем нужны эти правила

Неподготовленный пользователь может не понимать, для чего это всё. Коротко: каждое правило закрывает типичную дыру.

**Глобальный `AGENTS.md`** — задаёт поведение агента в любом проекте:
- *Коммуникация* — лаконичные ответы на русском, без приветствий и воды: «senior-разработчик», а не болтливый ассистент.
- *Git* — перед работой агент проверяет состояние Git и делает коммит после каждого изменения; вам не нужно помнить, что работу надо «сохранить».
- *Python* — в Python-проекте агент проверит, что интерпретатор установлен, и предложит поставить при отсутствии — работа не обрывается на середине.
- *Project Bootstrapping* — в пустой папке агент уточнит, какой стек развернуть, и создаст проектный `AGENTS.md`, если его нет: контекст не теряется при переходе в новый чат.
- *README* — агент держит `README.md` в актуальном состоянии вместе с кодом, чтобы описание не превратилось в «мёртвый текст».
- *Оболочка Windows* — на Windows агент берёт ту оболочку (cmd или PowerShell), где операция короче и надёжнее (терминал Zed — POSIX и искажает Windows-пути).
- *Лимиты и экономия токенов* — агент работает экономно в адаптивном профиле по размеру контекстного окна (узкое ≤ 128K / стандартное 129–200K / широкое > 200K): пороговые триггеры (30/55/65% окна), handoff-протокол в новый чат, точечные чтения, ограниченные выводы терминала, планирование под квоту, параллельные tool-calls — экономия квоты и ускорение.

**Skills:**
- *`git-workflow`* — готовая последовательность настройки Git: установка, инициализация, `.gitignore`, настройки пользователя; агент следует ей, а не выдумывает.
- *`project-doctor`* — разовая диагностика среды: установлены ли зависимости, есть ли переменные окружения, какие линтеры; открыв проект, сразу видно, что делать.

## О MCP-серверах

Проект MCP-серверы не использует, и правила не требуют их: каждый сервер добавляет tool-схемы в контекст каждого запроса — при ограниченной квоте это постоянная трата токенов. Основой кодинг-воркфлоу Zed покрывает нативно (файлы, терминал, grep, диагностика, fetch). MCP полезен лишь в узких случаях (свежие доки библиотек, E2E-тесты браузера, работа с БД) — подключать можно на своё усмотрение в `%APPDATA%\zed\settings.json` (ключ `mcp_servers`; в старых версиях Zed — `context_servers`); сервер станет доступен в **новом** агент-чате.

## Как использовать (новая машина)

0. Получить проект: https://github.com/IgerOK/rules-zed → кнопка `Code` → `Download ZIP`
   (Git не нужен). Распакуйте архив в папку и откройте эту папку в Zed как
   проект (File → Open Folder).
1. Установить Zed: https://zed.dev/?ref=taaft (Windows — инсталлятор
   `Zed-x.x.x-windows-installer.exe` или портативный `.zip`; macOS — `.dmg`;
   Linux — `tar.xz`). Обновление — ставить **поверх** (не удалять `AppData\Roaming\Zed`
   и `AppData\Local\Zed` — там настройки, глобальный `AGENTS.md`, история чатов).
   Текущая версия: `Ctrl+Shift+P` → `Zed: About`.
2. Установить Git (если отсутствует): https://git-scm.com (Windows — инсталлятор;
   Linux — системный пакетный менеджер `apt`/`dnf`/`pacman`; macOS — `brew install git`).
3. В открытом проекте запустить **новый** агент-чат и сказать:
   *«Прочитай файл `rules-Zed.md` и выполни инструкции §1–§6.»* Агент по
   порядку создаст файлы (§1, §2, §5), сверит всё по чек-листу §6 и
   отчитается, что создано. Альтернатива — выполнить §1–§6 вручную; путь
   через агента проще для неподготовленного пользователя.
4. Настроить LLM-провайдера в Zed — по инструкции репозитория
   https://github.com/IgerOK/zed-free-llm (рекомендация: Agnes / `agnes-3.0-flash`);
   API-ключ вставляется только в настройки Zed и не попадает в файлы.
5. Открыть **новый** агент-чат и проверить результат: спросите у агента, какие
   skills доступны — в списке должны быть `git-workflow` и `project-doctor`.
   Список skills и правил фиксируется при создании треда и в уже открытых
   диалогах не обновляется (перезапуск Zed не помогает — старые чаты
   восстанавливаются со «замороженным» снимком).
6. После шагов 1–5 папка с проектом больше не нужна — её можно
   удалить: правила и skills уже установлены в глобальных каталогах
   (`%APPDATA%\zed\AGENTS.md` и `%USERPROFILE%\.agents\skills\` на Windows;
   на других ОС — в соответствующих `~`-путьях). Если канон понадобится
   снова — просто скачайте проект повторно (шаг 0).

## Проектные правила

Глобальный `AGENTS.md` покрывает общие правила. Для любого проекта (не только нового
кодинг-проекта) важно, чтобы в корне был файл `AGENTS.md` **с проектно-специфичным**
описанием: он держит контекст проекта (экономия токенов, бесшовный переход в новый чат).
Записывать туда только проектно-специфичное (то, что отличается от глобального, без дублирования):
- стек и версии (язык, фреймворки, версии тулов);
- точные команды сборки/запуска/тестов/линтинга (с флагами);
- конвенции проекта (именование, структура каталогов, запретные зоны);
- особенности окружения (имена переменных окружения **без значений**, порты, БД, CI);
- требования к формату ответов/отчётов.

Не дублировать глобальные правила (commit message, git check, лимиты моделей) —
источник правды один (глобальный `AGENTS.md`); держать файл актуальным и не
записывать в него секреты. Быстрый старт: попросить агента написать начальный
проектный `AGENTS.md` по правилам из глобального, затем проверить и дополнить.

## Конфиденциальность

Файлы проекта не содержат секретов: API-ключи и токенные значения передаются
только через настройки Zed (system keychain), а в документах стоят плейсхолдеры
(`<USER>`, `User Name`, `email@example.com`, «ваш ключ LLM»).
